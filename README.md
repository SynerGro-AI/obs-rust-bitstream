# obs-rust-bitstream

**Public foundation for the OBS Studio rewrite in Rust.**

Goal: beat the ~800 scripts already finished upstream by using ~10% of the API actions.  
**Work smarter, not harder.**

Reusable patterns + differential helper, and the Seraphina Studio desktop app.

## Desktop app: Seraphina Studio

A single egui/eframe window with six workspaces, a gold-on-black theme (plus
a light theme), a custom title bar, collapsible tool sections, a Maya-style
shelf and a live status bar. Windows is the primary target; it also runs on
Linux and macOS.

### Materials Lab and Physics Arena

**Data.** `src/element_data.rs` holds PubChem's periodic-table data for all
118 elements (mass, configuration, electronegativity, ionisation energy,
oxidation states, melting/boiling point, density, CPK colour).
`src/element_props.rs` is generated by `tools/gen_element_props.py` from
mendeleev and pymatgen (specific heat, thermal and electrical conductivity,
latent heats, Young's modulus, Poisson ratio, crystal structure, half-life of
the longest-lived isotope). Tests spot-check values against CRC/NIST figures
(Cu resistivity 1.7 µΩ·cm, Al cp 897 J/kg·K, Fe E ≈ 211 GPa, U-238
4.468 × 10⁹ y, …).

**Composition builder.** A formula (`H2O`, `Ca(OH)2`, `CuSO4[H2O]5`) or a
single atom from protons, neutrons and electrons is analysed for:
* nuclear stability (N/Z band, and whether a known isotope exists);
* net charge, and whether the formula can be charge-balanced from the
  elements' common oxidation states (a depth-first search);
* metallic bonding.

**Derived properties.** These are documented heuristics, not first-principles
results. They are tagged in the UI:
* Molar mass is exact.
* Density uses ideal volume mixing.
* Specific heat follows the Kopp–Neumann law.
* Metal colour comes from measured F0 reflectance (gold, copper, …).
* Dielectrics use F0 from the IOR.
* Gas density follows the ideal gas law.
* The boiling point under pressure follows Clausius–Clapeyron.

Presets (gold, copper, iron, aluminium, silicon, glass/SiO₂, water/ice,
graphite, diamond) use CRC handbook values.

**3D.** `material_assign` puts a library material, preset or formula on any
mesh. Shading is Blinn-Phong:
* Schlick Fresnel and energy-normalised specular;
* a sky/ground environment for reflections;
* metals tinted by F0 with no diffuse; dielectrics diffuse plus a weak
  Fresnel reflection;
* clear materials alpha-blended.

**Physics Arena** (`src/arena.rs`, 3D tools → Physics Arena). Every visible
mesh becomes a body with mass = density × mesh volume. Open meshes such as
planes are static. The arena models:
* gravity, quadratic air drag with wind, and buoyancy;
* ground and box contacts with restitution √(e₁e₂) and Coulomb friction
  √(μ₁μ₂);
* heating from a heater, convection and Stefan–Boltzmann radiation;
* melting and boiling with latent heat. Melted bodies slump into a puddle;
  boiled ones vaporise.

Environment presets are Earth, Moon, Mars, vacuum, space and custom. The
integrator is semi-implicit Euler at a fixed 1/240 s. Play/Pause/Step/Reset
are AppCommands (`arena_play`, `arena_step`, `arena_reset`, `arena_env`,
`arena_body`), so Seraphina can say "drop the cube on the Moon". Starting a
simulation is one undo step.

**Limits (honest):**
* Bodies translate only (no rotation).
* Contacts are axis-aligned boxes.
* Each body has one uniform temperature.
* Transparency is a blend (no refraction).
* A puddle's shape is a fixed proportion.
* Restitution and friction are per-category estimates.

**Scripts.** `ui --run file.jsonl` dispatches one AppCommand per line and logs
each result to stderr. Commands that need the user (file I/O, billing, going
live) are skipped. Demos live in `docs/scripts/`:
* `materials_scene.jsonl`: six materials in 3D;
* `arena_moon.jsonl`: hammer-and-feather on the Moon;
* `arena_melt.jsonl`: a 1 MW heater melts 30 cm of ice in ~9 s.


### Lab, Phase 2: energy, reactions, circuits, a computer, relativity

The Materials workspace has five tabs: **Elements | Reactions | Circuits |
Computer | Relativity**. Every control pushes an `AppCommand`, and Seraphina
has the same commands as tools: `lab_tab`, `chem_react`, `circuit_run`,
`cpu_run`, `cpu_heat_sweep`, `rel_speed`, `nbody_preset`, `nbody_play`,
`nbody_measure_precession`. These commands run simulations or change the
view, so they have no undo entries. Demo scripts are in
`docs/scripts/lab_*.jsonl`; run them with `ui --run <file>`.

- **Energy ledger** (in the 3D Physics Arena card). Stocks: kinetic energy,
  buoyancy-corrected potential energy, and internal energy (m·c·T plus
  latent heat). Flows: heater, air/radiation exchange, drag work, impact
  heat, conduction. The residual (stocks − start − flows) stays below 1e-4
  of the total. The limit is f32 positions.
- **Reactions** (`src/chem.rs`). Equations are balanced exactly with
  rational arithmetic. Data come from CODATA/NIST-JANAF/CRC for 40
  species. Gas Cp(T) uses the rigid-rotor/harmonic-oscillator model with
  vibrational frequencies. The stable phase is the one with the lowest G(T).
  The program computes ΔH, ΔS, ΔG and K. Published global rate laws
  (Westbrook–Dryer, Marinov H2, first-order N2O5) drive an adiabatic
  constant-pressure reactor that stops at equilibrium, and the adiabatic
  flame temperature includes the melting and boiling plateaus.
- **Circuits** (`src/circuit.rs`). Modified nodal analysis with Newton
  iteration and backward-Euler transients. Components: R, C, L, V and I
  sources, a Shockley diode, an EKV MOSFET with temperature effects, wires
  with R = ρ(T)·L/A from the element's resistivity, Joule heating that can
  melt a fuse open, and doped silicon (Varshni band gap, n_i,
  Caughey–Thomas mobility).
- **Computer** (`src/computer.rs`). CMOS INV/NAND2/NOR2 cells are
  characterised at transistor level (transfer curve, noise margins, delay
  into 20 fF, leakage). Those delays drive an event-driven gate-level
  simulation of a 9-NAND full adder and a 4-bit add/sub ALU (52 gates).
  On top sit NAND master-slave registers and a 4-bit accumulator CPU with
  an assembler. The CPU samples the gate-level ALU at each clock edge,
  so heat or overclocking produce real wrong answers: timing first, then
  logic levels, then intrinsic silicon. `die_object` ties the die
  temperature to a body heated in the 3D arena.
- **Relativity** (`src/relativity.rs`). Special-relativity readouts (γ,
  time dilation, contraction, energy, Doppler, velocity addition).
  Newtonian N-body uses symplectic leapfrog, or RK4 with the first
  post-Newtonian (Schwarzschild) term. Presets: Mercury, inner planets,
  Earth–Moon, figure-eight, binary. The Mercury run measures 42.98″/century
  of GR perihelion advance. There are also GPS clock rates and light
  deflection.

See `docs/UI_FUNCTION_TEST.md` v5 for what is exact and what is
approximate.

### How the AI is wired in

* **One command bus.** Every button, shortcut, drag and AI action becomes an
  `AppCommand` (`src/bin/ui/commands.rs`) and goes through `App::dispatch`.
  The AI can only do what a command allows; a few commands, such as
  `set_stream_key`, are UI-only and not offered to it.
* **Tool calling.** The 101 commands are exposed as JSON-schema tools to an
  OpenAI-compatible chat API (list: [docs/AI_TOOLS.md](docs/AI_TOOLS.md)). Calls run through a Triad gate:
  * the call must parse;
  * file I/O (open, save PSD, export PNG), billed generation (video, image,
    extend, stitch), going live and starting a recording need the user to
    press **Run** on the action card;
  * dispatch must succeed, and failures are reported back to the model.
* **Undo.** Each AI turn snapshots the document state, and **Undo** on the
  action card reverts the whole batch.
* **Live learning.** A local `MercyLearningHeart`-style EMA store
  (α = 0.382) is updated incrementally from:
  * your tool and parameter choices;
  * 👍/👎 ratings;
  * AI actions you keep or undo. A batch counts as kept once you send your
    next message.

  A summary is injected into the system prompt. The status bar shows
  "Online learning: N updates". It is stored in
  `~/.seraphina/studio/mercy_bank.json`.
* **Seraphina.AGI CLI bridge.** If `seraphina` (`pip install seraphina-agi`)
  is on PATH, or set via `SERAPHINA_CLI`, its native intents (`remember …`,
  `recall`, `triad …`, `help`, `version`) are forwarded to it. Recent
  `recall` notes are added to the prompt.

| Variable | Default | Purpose |
|----------|---------|---------|
| `XAI_API_KEY` (or `SERAPHINA_GROK_API_KEY`) | none | Enables the LLM and Grok Imagine. Never committed; read from the environment only |
| `SERAPHINA_MODEL` / `SERAPHINA_GROK_MODEL` | `grok-4.7` | Chat model |
| `SERAPHINA_BASE_URL` / `SERAPHINA_GROK_ENDPOINT` | `https://api.x.ai/v1` | Any OpenAI-compatible server (a local server works without a key) |
| `SERAPHINA_NO_STREAM` | unset | Disable SSE streaming |
| `SERAPHINA_VIDEO_MODEL` / `SERAPHINA_VIDEO_RESOLUTION` | `grok-imagine-video-1.5` / `480p` | Video generation |
| `SERAPHINA_IMAGE_MODEL` | `grok-imagine-image-2.0` | Image generation |
| `SERAPHINA_CLI` | `seraphina` | Seraphina.AGI CLI program |
| `SERAPHINA_STUDIO_PREFS` / `SERAPHINA_HOME` | `~/.seraphina` | Learning store location |
| `SERAPHINA_NATIVE_FRAME` | unset | Use the OS title bar instead of the custom one |
| `SERAPHINA_MODE` / `SERAPHINA_LIGHT` | Paint / dark | Start mode and theme |

### Recording and streaming (ffmpeg)

Record and Go live run `ffmpeg` as a subprocess. The active mode's canvas is
letterboxed to the output size (default 1280×720, 30 fps) and piped as raw RGBA
to ffmpeg's stdin; a tick that can't be written in time counts as a dropped
frame. Alternatively ffmpeg grabs the screen (x11grab / gdigrab). Encoding is
libx264 (veryfast, zerolatency) + AAC (silent track by default); recordings are
MP4, live output is FLV over RTMP. `-progress` output drives the status bar.
A dropped live connection is retried with backoff (`Reconnect`, default 2 s,
10 attempts); *Retry now* reconnects immediately.

* ffmpeg lookup: `SERAPHINA_FFMPEG`, next to the exe (or `./ffmpeg/bin/`), then
  `PATH`. Missing ffmpeg gives a clear error with download links.
* Settings ▸ Output: RTMP URL, stream key, size, fps, bitrate, audio, record
  folder, reconnect. Saved in `~/.seraphina/studio/output.json`; the key lives
  alone in `~/.seraphina/studio/stream_key` (0600 on Unix), is shown masked,
  is scrubbed from ffmpeg error text and never reaches the AI context or logs.
  `set_stream_key` is UI-only (no AI tool).
* All of it goes through the AppCommand bus (`set_recording`, `set_streaming`,
  `retry_stream`, `set_output_source`, `set_stream_target`); starting output
  from Seraphina needs the user's approval.

### Run on Windows (recommended)

1. Install Rust with [rustup](https://rustup.rs) (`rustup-init.exe`). Keep the default
   **MSVC** toolchain (`stable-x86_64-pc-windows-msvc`). If prompted, install the
   Visual Studio Build Tools workload “Desktop development with C++”.
2. In PowerShell:

   ```powershell
   git clone https://github.com/SynerGro-AI/obs-rust-bitstream.git
   cd obs-rust-bitstream
   $env:XAI_API_KEY = "<your key>"   # optional, enables Seraphina + Grok Imagine
   cargo run --release --features ui --bin ui
   ```

For Record / Go live put `ffmpeg.exe` next to the exe or on PATH (see
`packaging/windows/README.txt`). The release build is `target\release\ui.exe`. It looks for `assets\` and the
sample streams (`out.h264`, `out.obsr`) in the working directory, next to the
exe, or up to four folders above it. Copy them alongside the exe to ship it.
Release builds on Windows use the GUI subsystem, so no console window opens.

Optional: `--features "ui windows"` also builds the Media Foundation camera
capture code.

### Run on Linux / macOS

```bash
cargo run --release --features ui --bin ui
```

Linux needs an X11 or Wayland session with OpenGL. On minimal installs:
`sudo apt install libxkbcommon-x11-0 libgl1 libegl1`.

### Cross-compile a Windows .exe from Linux

```bash
sudo apt install mingw-w64
rustup target add x86_64-pc-windows-gnu
cargo build --release --features ui --bin ui --target x86_64-pc-windows-gnu
# -> target/x86_64-pc-windows-gnu/release/ui.exe
```

### Tests

```bash
cargo test --lib                       # library
cargo test --features ui --bin ui      # UI, command bus, AI agent (mock provider), headless
```

Tests that need an outside program fail with a message saying what is
missing; they never pass silently.

* **ffmpeg** (or `SERAPHINA_FFMPEG`) is required by
  `records_five_seconds_to_mp4_verified_by_ffprobe` (5 s to MP4, checked with
  ffprobe) and `goes_live_to_an_ffmpeg_rtmp_listener` (goes live to
  `ffmpeg -listen 1` on 127.0.0.1 and checks the received FLV with ffprobe).
* **mediamtx** at `~/opt/mediamtx/mediamtx` (or `MEDIAMTX`) is required on
  Linux by `streams_to_local_rtmp_and_reconnects_with_backoff`: it streams to a
  local RTMP server, confirms receipt under the stream key, kills the server
  and checks the reconnect.

On Windows (and under Wine) the ffmpeg and mediamtx tests are reported as
ignored with the reason. Every other opt-in test is `#[ignore]` with its
reason in the attribute, and fails if what it needs is missing:

```bash
# live, billed: need XAI_API_KEY
cargo test --features ui --bin ui -- --ignored live_xai_tool_calling_smoke
cargo test --features ui --bin ui -- --ignored live_xai_smoke_test
SERAPHINA_LIVE_OUT=/tmp cargo test --features ui --bin ui -- --ignored live_imagine
# live, free (/models): needs XAI_API_KEY
cargo test --features ui --bin ui -- --ignored live_xai_key_test
# needs the Seraphina.AGI CLI (pip install seraphina-agi)
cargo test --features ui --bin ui -- --ignored real_cli_intents_end_to_end chat_routes_memory
```

## CI: Grok PR review

`.github/workflows/grok-review.yml` runs on every pull request. It installs
the Grok CLI from `https://x.ai/cli/install.sh` and asks it to review the PR
for bugs. The job has `contents: read` and `pull-requests: write`
permissions so it can post the review.

**Required setup:** add the repository secret **`XAI_API_KEY`** under
GitHub → Settings → Secrets and variables → Actions → New repository
secret. Without it the review step fails. GitHub does not pass secrets to
workflows triggered from forks, so pull requests from forks skip the
authenticated review.

## Parser

`tools/obs_cpp_to_rust_parser.py` loads `tools/lessons.json` and generates
Rust skeletons that already document the learned fixes. Add new lessons
as you discover more quirks — the next parse gets smarter automatically.

## Layout

```
src/lib.rs        library modules (listed above)
src/bin/ui/       Seraphina Studio (the desktop app)
src/bin/run.rs    terminal demo of the encode/stream status pipeline
src/bin/ai_write.rs, raw_read.rs, slice.rs   small dev tools
examples/         numeric checks for the arena, chemistry, CPU, relativity
tools/            the OBS C-to-Rust parser and the element-data generator
```

## Trial download

A prebuilt Linux binary is in `dist/obs-rust`.

```bash
git clone https://github.com/SynerGro-AI/obs-rust-bitstream.git
cd obs-rust-bitstream
chmod +x dist/obs-rust
./dist/obs-rust
```

It prints the shell status, platform targets, and a 💭 instruction for the active tool.

To build from source (any OS):

```bash
cargo build --release --bin run
./target/release/run
```
